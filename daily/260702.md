## 1. AWS IVS 공식 SDK 지원 사양

* **배포 방식 및 도구:**
  * **iOS (Swift):** **CocoaPods 미지원(배포 중단)**, **SPM (Swift Package Manager)**을 통한 배포 공식 권장.

    ```gradle
    implementation 'com.amazonaws:ivs-broadcast:1.43.0:stages@aar'

## 2. 네이티브 SDK 핵심 API 제공 여부
네이티브 SDK 자체에서 아래 기능들을 완벽히 기본 API로 내장하고 있으므로, 브릿지 설계 시 참고해.
1. **카메라 프리뷰 (Camera Preview):**
   * `IVSImagePreviewView` 객체 획득 가능. (Android: `((ImageDevice)device).getPreviewView()`를 호출해 안드로이드 `View`로 바로 레이아웃에 추가 가능)
2. **디바이스 선택 및 전/후면 카메라 전환:**
   * `BroadcastSession.listAvailableDevices()`로 하드웨어 목록 조회 가능.
   * `session.exchangeDevices(oldDevice, newDevice, callback)` API를 제공하여 부드러운 카메라 전환 제어 지원.
3. **재연결 (Reconnect) 메커니즘:**
   * 네트워크 유실 시 자체적으로 **자동 재연결(Auto-Reconnect) 루프**가 내장되어 있음.
   * 브릿지에서는 `state` 변화 이벤트(connected, disconnected, reconnecting)를 캐치하여 JS단에 이벤트를 보내주기만 하면 됨.

## 3. 아키텍처 비교 의사결정: React Native CLI vs Expo (Prebuild)
PM님께 **"Expo (Config Plugin + Prebuild/Development Builds)"** 방식을 권장드렸고, 타당성 근거는 다음과 같아.

### A) React Native CLI (Bare)
* **장점:** Xcode와 Gradle 파일을 100% 직접 제어하여 공식 문서 가이드를 그대로 이식 가능.
* **단점:** CocoaPods Deprecation 조치에 따라 SPM 의존성을 수동 관리해야 하여 iOS 빌드 설정 오버헤드가 극도로 심해짐. RN 메이저 업그레이드 시 수동 머지 부담.

### B) Expo (Prebuild + Config Plugin) - ★강력 추천
* **장점:** 
  1. **SPM 공식 대응:** Expo SDK 56+은 SPM 의존성 주입을 선언적으로 완벽히 지원하여 CocoaPods 배포 중단 리스크 방어 가능.
  2. **Expo Modules API (Sweet API):** 레거시 브릿지에 비해 코드량이 적고 타입 안전한 Swift/Kotlin 모듈 작성 가능.
  3. **유지보수:** `app.json`을 통해 카메라/마이크 권한 및 Target iOS 버전을 자동 주입하고, 필요 시 `prebuild`로 네이티브 폴더 재구성 가능.
* **단점:** 초기 SPM 및 AAR 라이브러리 연동용 Config Plugin을 구현하는 초기 리스크/공수 존재.

### C) 구현 추천 방향
* `expo-realtime-ivs-broadcast` 오픈소스 래퍼(Unstable)의 네이티브 바인딩 구조를 벤치마킹하여, **Expo Modules API 기반의 Custom Native Module** 형태로 브릿지를 직접 구현할 것.
