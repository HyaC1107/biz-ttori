### [[projects/fanbird-broadcast]] [클또리] — Android 전화 인터럽트 **진짜 근본원인=스레딩 버그(10012)** 규명·수정 (실기기 검증 완료)
- 위 마이크 storm 수정 후 실기기 재테스트: storm은 **221회→0회**로 잡혔으나 **방송은 여전히 통화 중 끊기고 복구 안 됨**(시청자 방송종료). storm은 증상이었고 진짜 killer는 따로 있었음.
- **진단**: IVS 상태 리스너(`onStateChanged`/`onError`/`onRetryStateChanged`)에 임시 logcat 로깅(`IvsIngestTest`) 추가 후 재테스트 → 전화 받는 순간 `onError: code=10012 "Broadcast API called from a thread other than the one it was created on"`가 수십 번 터지고 즉시 `DISCONNECTED` 확인.
- **근본원인**: IVS 세션은 `IvsBroadcastModule`이 모든 조작을 `UiThreadUtil.runOnUiThread`로 감싸 **메인 스레드 소유**인데, `AudioManager.OnAudioFocusChangeListener` 콜백은 메인이 아닌 스레드로 와서(minSdk 24: deprecated 경로 포함), 거기서 `detachMicrophoneForInterruption`/`setCameraEnabled` 등 IVS API를 직접 호출 → IVS 스레드 규칙 위반(10012) → 세션 즉사. (네트워크/OS 서스펜드 문제가 **아님**)
- **수정**: `IvsBroadcastController.kt` — `runOnSessionThread{}` 헬퍼 추가(`Looper.myLooper()==mainLooper` 아니면 `mainHandler.post`), AudioFocus LOSS/GAIN 핸들러의 모든 IVS 조작(placeholder 활성/해제, 마이크 detach/reattach)을 이 헬퍼로 감싸 메인 스레드에서 실행.
- **실기기 검증 완료(test3, 통화 17초)**: IVS `onError` **0건**, 통화 구간 내내 `DISCONNECTED` 없이 **CONNECTED 유지**, 통화 후 마이크 재부착·카메라 복원 정상, 방송 계속 유지(29초 뒤 PM 수동 종료). → **Android 전화 인터럽트 배포 블로커 해소.**
- 후속 ①: 임시 진단 로깅(`IvsIngestTest`) 제거 완료(`./gradlew :app:compileDebugKotlin` 재확인).
- 후속 ②: iOS 코드 리딩으로 동일 버그 여부 선검토 — **iOS는 구조적으로 안전**. `IVSBroadcastModule.swift`가 `methodQueue { .main }`(+`requiresMainQueueSetup() = true`)로 세션을 메인 큐에서 생성하고, `IVSBroadcastController.swift`의 오디오 인터럽트 옵저버도 `NotificationCenter.addObserver(..., queue: .main)`으로 명시 등록 — 세션 생성 스레드와 콜백 스레드가 애초에 동일(둘 다 메인). Android처럼 `AudioFocusChangeListener`에 스레드 미지정으로 어긋나는 구조 자체가 없음. 다만 코드 리딩 결론이라 실기기 검증은 그대로 필요 — iOS 실기기 테스트는 "10012 버그"보다 "마이크 통화 중 detach·재부착 자연스러운지"(Android처럼 storm 나는지) 위주로 확인 예정.
