### [[projects/fanbird-broadcast]] [PM+클또리] — 상품 팝업-영상 동기화 신규 구현 (Timed Metadata, 실기기 검증 완료)
- **배경(PM 문제 제기)**: 관리자 웹에서 "판매노출" 클릭 시 소켓(Stock/Stock Over)이 방송 지연(2~3초)과 무관하게 즉시 도착해, 시청자 화면에서 쇼호스트가 실제로 말하는 영상 순간과 상품팝업 타이밍이 어긋나 있었음.
- **설계**: 소켓은 방송 지연과 별개 경로라 안 맞는 게 근본원인 → §6/7에 쓴 것과 같은 **IVS Timed Metadata**로 전송 경로를 바꿔, 팝업 신호가 영상 스트림 자체에 실려 각 시청자의 재생 지연만큼 자연히 늦게 도착하게 함.
  - **송출앱**: 소켓 `Stock`/`Stock Over` 수신 시 셀러 본인 화면(지연 없음)은 그대로 즉시 반영하고, **동시에 원본 이벤트(`action`+`item`)를 그대로** `sendTimedMetadata()`로 스트림에도 실어보냄. "Stock Over는 판매노출 상태일 때만 반영" 같은 기존 조건판단은 임의로 재해석하지 않고 데이터만 그대로 전달.
  - **네이티브**: iOS/Android 컨트롤러에 JS가 호출 가능한 범용 `sendTimedMetadata(payload)` 신규 브릿지 추가(기존 카메라/마이크 mute 전송 로직과 공유).
  - **close 웹**: `Live_Component.tsx`가 `TEXT_METADATA_CUE`로 수신 → 콜백(`on_product_metadata`)으로 `Live.tsx`에 전달 → 기존 소켓 핸들러와 동일한 조건 로직 그대로 적용, 기존 `Stock`/`Stock Over` 소켓 리스너는 제거(동시에 있으면 소켓이 먼저 도착해 의미 없음). 초기 진입 시 현재상태 스냅샷(`is_visable_product` REST 조회)은 그대로 유지 — 메타데이터는 "그 순간 한 번"만 실리므로 중간 입장 시청자를 위한 안전망으로 계속 필요.
- **버그 발견·수정**: iOS 실기기 테스트에서 `TypeError: undefined is not a function` — Swift `@objc` 메서드를 추가해도 iOS는 Objective-C 브릿지 파일(`IVSBroadcastModule.m`)에 `RCT_EXTERN_METHOD`로 별도 등록해야 JS에서 호출 가능한데 이 등록을 빠뜨림(Android는 `@ReactMethod` 하나로 자동 등록돼 문제없었음). 등록 추가로 해결, **iOS 실기기 확인**.
- **검증**: **PM 실기기 확인(iOS+Android)** — 팝업이 소켓 대비 훨씬 정확한 타이밍에 뜸. 체감 오차 0.1~0.2초 수준으로, 인코더 큐잉·플레이어 이벤트 디스패치 등 스트리밍 메타데이터 구조 자체의 고유 지연으로 판단(코드로 더 줄이기 어려운 영역, PM도 이 정도 오차는 감수하기로 함).
