* **[잔여 기능] Android 포그라운드 서비스/알림 신설**: 기존엔 관련 코드가 아예 없었음(카메라/마이크 권한만 있고 `FOREGROUND_SERVICE` 계열 권한·서비스 선언 전무).
  * `android/app/.../BroadcastForegroundService.kt` 신설 — "라이브 방송 중" 상시 알림(`NotificationChannel` IMPORTANCE_LOW), API 29+에서는 `FOREGROUND_SERVICE_TYPE_CAMERA|MICROPHONE` 명시.
  * `IvsBroadcastModule.kt`의 `startSession`/`stopSession`에서 서비스 시작/종료 연동.
  * `AndroidManifest.xml`에 `FOREGROUND_SERVICE`/`FOREGROUND_SERVICE_CAMERA`/`FOREGROUND_SERVICE_MICROPHONE`/`POST_NOTIFICATIONS` 권한 + `<service>` 선언(`foregroundServiceType="camera|microphone"`) 추가.

## 5. 🤖 클또리 작업 내역 (fanbird-broadcast — PM 안드로이드 실기기 QA 중 발견분 추가 수정)

PM이 실기기로 직접 검증하면서 나온 후속 이슈들. 전부 처리 완료, 안드로이드 실기기로 검증됨.

* **알림 권한이 요청 안 됨**: 카메라/마이크가 이미 승인된 기기(예전 테스트 기기)에서는 `checkAndRequestAVPermissions`가 AV 권한만 보고 바로 통과시켜, 오늘 추가한 `POST_NOTIFICATIONS` 요청까지 도달을 못 했음. `ensureAndroidNotificationPermission()`을 신설해 AV 권한 상태와 무관하게 방송 시작 시 항상 독립적으로 확인·요청하도록 수정 (`IVSBroadcastModule.ts`, `BroadcastScreen.tsx`).
* **방송 종료 후 라이브목록이 자동 새로고침 안 됨**: `LiveListScreen.tsx`의 데이터 로드가 mount 시 1회만 도는 `useEffect`였는데, 방송화면에서 `navigate('LiveList')`로 돌아오면 스택에 있던 기존 인스턴스를 재사용(리마운트 아님)해서 재실행이 안 됐음. `useFocusEffect`로 교체해 화면 포커스마다 새로고침.
* **"방송중" 라이브를 목록에서 재진입할 방법이 없음**: 액션 버튼이 "예약" 상태에만 노출되던 구조라, 뒤로가기로 나간 뒤 방송중 항목을 다시 못 눌렀음. "방송 화면으로" 버튼을 신설(우측 정렬)해 재진입 가능하게 함 (`LiveListScreen.tsx`).
* **오늘 예약 슬롯 소진 이슈**: 반복 테스트로 오늘 날짜 예약 가능 시간대가 다 막힘. `/unavailable_time`이 종료/취소 상태와 무관하게 슬롯을 막는 것으로 추정, "종료" 상태에도 임시로 취소 버튼을 노출해봤으나(`isTempDeletableEnded`) 백엔드가 "예약" 상태가 아니면 취소 자체를 거부 — 프론트에서 우회 불가로 백엔드 확인 필요 판단.
* **앱 강제종료 시 서버 상태 불일치 확인**: 방송 중 앱을 태스크킬하면 네이티브 세션(실제 송출)은 끊기지만, 정상 종료 API를 호출할 기회가 없어 서버 `live_status`는 "방송중"으로 남는 걸 확인 — 구조적 한계로, 하트비트/AWS IVS 실제 스트림 상태 확인 같은 백엔드 보완이 필요할 수 있음.
* **iOS 백그라운드 한계 재확인**: 앱 내 화면 전환(뒤로가기)은 iOS도 세션이 안 끊기지만(Swift `IVSBroadcastController`도 동일하게 `teardownIfIdle` 방송중 no-op), 앱을 완전히 백그라운드로 보내면 `UIBackgroundModes` 미선언으로 OS가 카메라를 곧 정지시킴 — 기존에 알려진 플랫폼 제약, 오늘 이슈 아님.
