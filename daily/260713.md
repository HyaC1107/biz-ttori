### projects/fanbird-broadcast — Android 블루투스 이어폰 마이크 무음 + 자동전환 시 오류 팝업

- **원인 1(공식 문서 확인)**: AWS IVS Android Broadcast SDK는 블루투스 마이크 사용 시 앱이 직접 `Bluetooth.startBluetoothSco(context)`를 호출해야 한다고 명시돼 있음 — SDK가 알아서 켜주지 않음. 코드에 이 호출 자체가 없었음.

- **조치**: `IvsBroadcastController.kt`에 `startBluetoothScoAndWait()` 추가 — SCO 연결 완료(`SCO_AUDIO_STATE_CONNECTED`, 3초 타임아웃 폴백)를 기다린 뒤에 마이크 교체하도록 순서 변경. 세션 종료 시 SCO도 같이 정리.
- **부수 버그**: 블루투스 마이크가 빠질 때 자동전환이 복구를 완료하기 전에 SDK가 먼저 `onError`를 쏴서 "송출오류" 팝업이 잠깐 떴다 사라짐 — 자동전환 감지 시점부터 2초간 에러를 JS로 전달하지 않도록 억제 로직 추가.
- **상태**: 코드 작성 완료, **실기기 검증 아직 안 됨**(다음 세션에서 확인 필요).

### 다중 마이크 위치 선택 — 결국 "SDK 제약"이 아니라 RN 브릿지 버그였음
- 처음엔 iOS/Android 둘 다 SDK/OS 오디오 API 레벨 제약으로 진단해서 iOS만 애플 API로 보정하고 Android는 "API가 없어서 CustomAudioSource 우회 필요, 비용 대비 효과 낮음"으로 보류 결정까지 했었음. 하지만 실기기 로그(IVS SDK가 마이크 3개를 정확히 별개 URN으로 내려주고 있었음)로 재검증한 결과, 진짜 원인은 훨씬 단순한 RN 프리뷰 뷰의 prop 반영 누락이었음 — 두 플랫폼 다 저비용으로 완전히 해결됨.
- **교훈**: "이 플랫폼은 원래 안 되는 제약"이라고 결론 내리기 전에, 실기기 로그로 SDK가 실제로 뭘 하고 있는지부터 확인할 것. 리서치(젬또리) 답변뿐 아니라 클또리 자신의 1차 진단도 재검증 없이 확정하면 안 됨.

### AWS IVS 방송 종료 30초 지연 — 플랫폼 동작일 가능성 높음, 우회는 앱 UX 레벨에서만 가능
