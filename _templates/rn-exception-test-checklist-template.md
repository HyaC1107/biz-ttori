# [RN 앱 예외상황 테스트 체크리스트] {프로젝트명}

> **용도**: 새 React Native 프로젝트가 실기기 테스트 단계에 들어갈 때, "뭘 테스트해야 하는지" 항목을 뽑는 표준 체크리스트.
> fanbird-broadcast(송출앱) 실기기 테스트 과정(2026-07-10~16)에서 실제로 겪은 이슈를 일반화해 정리했다.
> **이 문서 자체엔 결과를 적지 않는다** — 항목을 골라 `_templates/test-report-template.md`로 옮겨 실제 결과(✅/⚠️/❌)를 기록한다.
>
> 구성: **Part A(범용)**는 카메라/스트리밍 여부와 무관하게 모든 RN 앱에 적용. **Part B(미디어 확장)**는 카메라·마이크·실시간 스트리밍을 다루는 앱에서만 선택 적용.

## Part A — 범용 RN 베이스라인 (모든 앱 공통)

### A1. 생명주기 / 포그라운드-백그라운드 전환
| 항목 | 테스트 방법 | 비고 |
|---|---|---|
| 백그라운드 전환 후 복귀 | 홈 버튼으로 백그라운드 전환 → 재진입 시 상태 유지 확인 | 미디어 앱은 A/V 정지·재개 정책 함께 확인 |
| 강제 종료 후 재시작 | 앱 스와이프로 강제 종료 → 재실행 시 크래시/깨진 상태 없는지 | |
| 딥링크/알림 탭 재진입 | 백그라운드에서 딥링크·푸시 탭으로 특정 화면 재진입 | |
| Fast Refresh 오탐 구분 | Metro dev 중 JS 저장으로 상태가 리셋되는 현상은 **dev 아티팩트**이지 실배포 버그가 아님 — release 빌드로 재확인 없이 버그로 오판하지 않도록 주의 | fanbird 260713 사례 |

### A2. 권한
| 항목 | 테스트 방법 | 비고 |
|---|---|---|
| 최초 권한 요청 거부 | 권한 팝업에서 거부 선택 시 대체 UI/안내 노출 | |
| 영구 거부 후 재진입 | 설정에서 권한 끄고 화면 재진입 → 안내 노출 확인 | |
| 미로그인 상태 접근 | 로그인 없이 접근 가능한 화면에서 오류 팝업 대신 안전한 fallback(빈 리스트 등) 노출 | close 프로젝트 사례(260710) |

### A3. 네트워크
| 항목 | 테스트 방법 | 비고 |
|---|---|---|
| 완전 단절 후 복구 | 비행기모드 토글로 강제 단절 → 복구 시 자동 재연결 확인 | |
| 단절 중 UI 처리 | 단절 상태에서 사용자에게 상태를 알리는지(무한 로딩으로 방치되지 않는지) | |
| 약한 네트워크 | 3G 시뮬레이션 또는 네트워크 스로틀링 하에서 핵심 플로우 동작 확인 | |
| API 타임아웃 | 타임아웃 발생 시 재시도/에러 안내가 있는지 (무한 대기 금지) | |

### A4. 인터럽트
| 항목 | 테스트 방법 | 비고 |
|---|---|---|
| 전화 수신/종료 | 통화 인터럽트 전/중/후 앱 상태 확인 | 오디오/카메라 다루는 화면은 Part B 참고 |
| 알람/타이머 오버레이 | 시스템 알람이 화면을 덮었다 사라진 후 앱 상태 확인 | |
| 타 앱 알림 팝업 | 알림 배너로 인한 레이아웃 밀림/터치 오작동 없는지 | |

### A5. 플랫폼/디바이스 편차
| 항목 | 테스트 방법 | 비고 |
|---|---|---|
| iOS/Android 동작 차이 | 동일 기능이 두 플랫폼에서 동일하게 동작하는지 | 특히 네이티브 브릿지 있는 기능 |
| 노치/펀치홀/폴드 레이아웃 | 버튼 겹침·잘림 여부 | Z Fold류는 접힘/펼침 둘 다 확인 |
| 상태바 가시성 | 밝은/어두운 배경 화면 각각에서 상태바 아이콘 시인성 | |

## Part B — 미디어/실시간 스트리밍 확장 (카메라·마이크·송출 다루는 앱만)

> 카메라/마이크를 켜거나 실시간 스트리밍(IVS, WebRTC 등)을 다루는 화면이 있는 프로젝트에서만 적용.

### B1. 인터럽트 중 미디어 파이프라인
| 항목 | 테스트 방법 | 비고 |
|---|---|---|
| 전화 수신 중 스트림/녹화 소실 여부 | 통화 중(15초 이상) 시청자단/저장본에 끊김 없는지 | fanbird: Android AAudio 캡처 스트림 storm(초당 13~18회 강제종료·재생성)이 근본원인이었던 사례 있음 — 단순 "복구됨" 확인에 그치지 말고 로그로 재발 패턴 확인 |
| 인터럽트 종료 후 자동 복구 | 통화 종료 후 별도 조작 없이 정상 송출/녹화 재개 | |
| 백그라운드 전환 중 대체 화면 | 카메라 끊긴 자리에 placeholder(정지 이미지 등)가 들어가는지, 오디오는 유지되는지 | |

### B2. 발열
| 항목 | 테스트 방법 | 비고 |
|---|---|---|
| 장시간 연속 송출/녹화 | 30분+ 연속 구동 후 발열 단계 도달 여부·소요시간 기록 | fanbird 실측: S22 37분에 CRITICAL 도달 |
| 발열 단계별 UI 경고 | SEVERE/CRITICAL 등 단계별로 사용자에게 경고 노출되는지 | 시청자단엔 노출 안 함이 일반적(정책에 따라 조정) |

### B3. 네트워크 저하 (완전 단절이 아닌 "불안정")
| 항목 | 테스트 방법 | 비고 |
|---|---|---|
| 저대역폭 경고 배너 | 비트레이트 하한 미달이 일정 시간(예: 3초) 지속될 때만 경고 — 순간 튐에 오탐 없는지 | 디바운스 없이 즉시 트리거하면 깜빡임/오탐 발생 |
| 장면 탓 vs 네트워크 탓 구분 | 단순한 화면(정지 장면 등)에서 비트레이트가 자연히 낮아지는 것과 실제 네트워크 저하를 구분하는 신호를 쓰고 있는지 | fanbird: `networkHealth` 사용, `measuredBitrate` 단독으론 오탐(정지 화면은 압축 잘 됨) |
| 카메라 재활성화 직후 오탐 | 카메라 껐다 켤 때 인코더 재적응 구간(수 초)을 네트워크 저하로 오판하지 않는지 | 재활성 후 수 초간 판정 유예 필요 |
| 재연결 후 지연 고착 | 강제 단절 후 재연결 시 지연시간이 회복 안 되고 고정되는지 | 버퍼 끝 근처로 catch-up seek 필요할 수 있음 |

### B4. 블루투스/외장 오디오
| 항목 | 테스트 방법 | 비고 |
|---|---|---|
| 블루투스 이어폰/마이크 연결·해제 | 방송/녹화 중 연결·해제 시 자동 라우팅 + 안내 토스트 정확성 | 연결 방향(내장→외장 vs 외장→내장) 판정은 "최초 상태 가정"이 아니라 실시간 플래그로 판정해야 함(가정 방식은 시작부터 외장이면 뒤바뀌는 버그 있었음) |
| 연결 상태 오판 없는 재연결 | 블루투스 순간 끊김-재연결 시 불필요한 에러 팝업 안 뜨는지 | |

### B5. 카메라/마이크 끄기 상태 전파
| 항목 | 테스트 방법 | 비고 |
|---|---|---|
| 카메라 끄기 시 시청자단 화면 | 검은 화면 방치 대신 placeholder/안내 노출 | |
| 마이크 음소거 시 시청자단 안내 | 음소거 상태가 시청자에게 배지/토스트로 전달되는지 | |
| 상태 전파 지연 | 스트림에 실어보내는 방식(Timed Metadata 등)은 재생 지연만큼 늦게 도착하는 게 정상 — 소켓 등 별도 채널과 섞어 쓰면 타이밍이 어긋날 수 있음 | |

### B6. 인코딩/성능
| 항목 | 테스트 방법 | 비고 |
|---|---|---|
| 인코딩 스펙 준수 | 콘솔에서 해상도/비트레이트/코덱 실측이 목표값과 일치하는지 | |
| 레이턴시 실측 | 재생 지연을 실측 API로 로깅해 목표치 이내인지 확인 | |
| 세션 종료 지연 | "종료" 조작 후 시청자단에 실제로 반영되기까지 걸리는 시간 확인 | 스트리밍 인프라 자체의 인제스트 유예로 인해 즉시 안 끊길 수 있음 — 클라이언트 신호(상태 폴링 등)로 UI를 먼저 덮는 방식이 필요할 수 있음 |

## 사용 방법

1. 새 프로젝트가 실기기 테스트 단계에 들어가면, 이 문서에서 해당하는 항목만 골라 `_templates/test-report-template.md`의 "기능별 테스트 결과" 섹션에 옮겨 붙인다.
2. Part B는 카메라/마이크/스트리밍이 없는 프로젝트라면 통째로 생략한다.
3. 테스트 중 여기 없는 새로운 예외 유형을 발견하면, 결과 기록(`test-report`) 후 **이 체크리스트에도 항목을 역으로 추가**해 다음 프로젝트에 재사용되게 한다.
