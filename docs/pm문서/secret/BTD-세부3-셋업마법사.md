# 🪄 BTD 세부기획 3 — 셋업 마법사 플로우

> **전제**: 진입점=로컬 웹 대시보드(`[[BTD-비전]]` §2). 마법사는 `@btd/web`(React)가 그리고 `@btd/server`가 파일을 실제로 만든다. init 파이프라인은 `[[BTD-세부1-팩규격]]` §4, 정적 팩(v1 자가발전 없음).

---

## 1. 진입 흐름 — `npx btd` 하나로 통합 (부트스트랩 해소)

브라우저는 파일을 못 만지므로 **항상 server가 먼저** 뜬다. cwd에 볼트가 있냐로 분기:

```
$ npx btd                    (cwd에서 실행)
   └ @btd/server 기동 (127.0.0.1:포트)
       └ 볼트 감지? (.btd/vault.json 마커)
           ├─ 없음 → 🪄 셋업 마법사 오픈
           └─ 있음 → 📊 관제 대시보드 오픈 (마법사 스킵)

$ npx btd init [--pack <id>] [--yes]   ← 헤드리스 대안(CI/스크립트용, 마법사 없이 동일 파이프라인)
$ npx btd pack add <name>              ← 정적 팩 스캐폴더(사람이 새 직군 팩)
```
> 즉 웹 마법사 = init 파이프라인의 GUI, `btd init` = 같은 파이프라인의 CLI. 로직은 `@btd/server`(+core) 한 곳, 프론트/CLI는 그 위 껍데기.

## 2. 마법사 화면 플로우 (7스텝)

```
[0 감지] ─ [1 볼트위치] ─ [2 직군선택] ─ [3 구성확인] ─ [4 에이전트] ─ [5 실행] ─ [6 doctor] ─ [7 완료]
```

| # | 화면 | 수집/행동 | 산출 |
|:---:|:---|:---|:---|
| 0 | **감지** | 볼트 유무·호환성 사전점검. 있으면 "관제로 이동 / 팩 추가 / 재설정" 제시(파괴 방지) | 분기 |
| 1 | **볼트 위치** | 기본=cwd. 비어있지 않으면 경고. 개인용 / 사내·팀내 모드 선택(비전 2형태) | 대상 경로 + 모드 |
| 2 | **직군 선택** | 번들 팩 카드 목록(v1=fullstack-rn). 선택 시 pack.yaml 로드→provides 요약 표시 | 선택 pack.yaml |
| 3 | **구성 확인** | 합성 미리보기: 어떤 rules 조각·템플릿·봇·스택이 깔리는지. `targetSkeleton` 호환 결과(🟢통과/🔴차단) | 확정 |
| 4 | **에이전트 설정** | 어떤 봇 쓰나(Claude Code·젬또리·…) + 선택 통합(Slack 등) | `agents.config.yaml`(③) |
| 5 | **실행(스캐폴딩)** | 뼈대 복사 + provides 합성 + 볼트 스키마 생성. **진행률 실시간 스트림** | 사용자 볼트(③) |
| 6 | **doctor 검사** | `gbrain-doctor` 1회. 통과율(예 46/46) 표시. 실패 시 원인 노출+재시도 | 무결성 확인 |
| 7 | **완료** | "관제 대시보드로 이동" → 마법사가 관제 뷰로 전환 | 마커 `.btd/vault.json` 기록 |

> 스텝 3의 "합성 미리보기"가 포폴 관점의 킬러 화면 — "규칙이 어떻게 조립되는지"를 눈으로 보여줌.

## 3. 세부2에서 넘긴 열린 질문 4개 — 결정

### Q1. 마법사 화면 단위 → **위 §2의 7스텝** (0감지 ~ 7완료)

### Q2. `web`↔`server` 실시간 채널 → **SSE(서버→클라 push) + HTTP POST(클라 액션)**
- 스텝5 진행률·스텝6 doctor 로그·관제 이벤트/헬스는 **서버가 미는 단방향** → **SSE**가 최적(ws보다 단순, 자동 재연결, 순수 HTTP).
- 버튼·우편 전송 등 클라→서버는 평범한 **HTTP POST**.
- ws는 진짜 양방향 저지연이 필요할 때만(현재 불필요) 도입. 기존 15초 폴링은 SSE로 대체. → **로컬앱에 과하지 않고 모던한 선택.**

### Q3. 레퍼런스 팩(fullstack-rn) 채우는 시점 → **첫 구현 마일스톤에 포함(뼈대 추출과 동시)**
- 마법사가 데모되려면 **실제 팩 1개가 전제**다. 그리고 그 자산은 대부분 **현재 biz-ttori의 ②버킷 파일 추출**(stack.md, test-report·rn-exception 템플릿, coder/reviewer/tester 페르소나, visual-validator).
- 즉 "팩 채우기"는 별도 후속이 아니라 **뼈대 추출 작업의 일부** → 첫 구현 때 같이 한다.

### Q4. init 멱등성 → **기본 멱등(사용자 파일 절대 비파괴)**
- 마커 `.btd/vault.json`로 설치 상태 추적.
- 재실행: 뼈대 파일은 **없을 때만 생성**(정적이라 있으면 skip), **사용자 데이터(③)는 절대 건드리지 않음**.
- "재설정"은 스텝0에서 **명시 확인 + 백업** 후에만. 기본 경로는 additive/no-op.
