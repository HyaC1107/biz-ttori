# 🧭 BTD (biz-ttori for Developer) — 비전 한 장

> **한 줄**: 지식 기반(G-Brain/Obsidian) 위에서, 직군별로 커스터마이징되는 **개인·팀용 AI 에이전트 워크스페이스**.
> 개발자는 **지시·검토**만 하고, 나머지 실작업은 구독한 에이전트들이 수행한다.
>
> 이 문서는 상위 비전을 한 장으로 압축한 것이다. 세부 스펙 잔재는 `[[agent_postbox_saas_plan]]`(옛 SaaS 기획, 참고용)에 있다.

## 0. 목적 — 판매가 아니다

| 우선 | 타깃 | 핵심 가치 | 협업층 필요? |
|:---:|:---|:---|:---:|
| ① | **포트폴리오** | "이 시스템을 설계·구현하고 실제 앱(fanbird)을 dogfooding하며 개발했다"는 설명력 | ✕ |
| ② | **프리랜서 개인** | 여러 클라이언트 프로젝트를 오가며, 위임할 팀 대신 **에이전트에 위임** | ✕ (혼자) |
| ③ | **사내 팀** | 팀 지식 연속성(사람 바뀌어도 컨텍스트 안 증발) + 온보딩 | △ (공유 git 레포면 충분) |

> ⚠️ **B2B SaaS·Stripe·상용화·경쟁사 가격·플랫폼 리스크 프레임은 버린다.** 팔지 않으므로 수익화 모순·플랫폼 흡수 리스크는 무관하다(오히려 빅테크가 유사 기능을 내면 "먼저 실증했다"는 포폴 근거).

### 0.1 v1 스코프 명시 — "BTD (Claude Code 에디션)" (2026-07-20 결정)

> **v1은 메인 에이전트=클로드 코드를 명시적으로 전제한다.** 숨겨진 한계로 두지 않고 **버전명에 명시**한다(예: "BTD — Claude Code Edition").
>
> **배경**: v1 뼈대는 `CLAUDE.md`·클로드 전용 `hooks.json` 스키마를 씀 → 암묵적으로 벤더종속. PM 지적으로 "벤더중립을 지금 다 풀지 말고, 대신 스코프를 정직하게 명명하자"로 결론. **거짓으로 벤더중립을 주장하는 것보다, "지금은 Claude Code판, 확장 아키텍처는 이미 검증됨"이 포폴 신뢰도상 더 낫다.**
>
> **다음 버전 아키텍처(검증 완료, 미구현)**: 볼트 루트 `AGENTS.md`를 캐노니컬 뼈대+팩 조립 결과물로, `CLAUDE.md`는 `@AGENTS.md` 1줄 import(Anthropic 공식 권장 패턴, `code.claude.com/docs/en/memory` "AGENTS.md" 섹션에서 확인)로 대체하면 Codex 등 AGENTS.md 호환 툴은 추가 작업 없이 자동 지원됨. `hooks.json`(클로드 전용 lifecycle 훅)은 이 방식으로도 안 풀림 — 별도 이슈로 남음. 상세: `BTD-v1-MVP.md` §7.

## 1. 3층 구조

```
┌─────────────────────────────────────────────┐
│ ③ 협업층 (사내 팀만)                          │
│    볼트 공유 · 팀원+봇 우체통 비동기 협업       │  ← 공유 git 레포로 시작 (CRDT/SOC2 X)
├─────────────────────────────────────────────┤
│ ② 직군 팩 (커스텀)                            │
│    풀스택 / AIoT(젯슨·라즈베리파이) / 기획 …    │  ← 초기 직군 선택 → 자동 세팅
│    기술스택 · 파생봇 · 템플릿 · 체크리스트       │     이후 툴이 스스로 환경 디벨롭
├─────────────────────────────────────────────┤
│ ① 뼈대 (공용, 직군 무관)                       │
│    지식그래프(안정앵커·계약·git추적) · 볼트     │  ← 여기가 해자(축적된 방법론)
│    우체통(inbox/outbox) · doctor 무결성 검사    │
└─────────────────────────────────────────────┘
```

- **①뼈대 = 해자.** "무엇을 링크하고 무엇을 링크하지 말지" 같은 축적된 규율(CLAUDE.md의 G-Brain 규칙)은 툴 플럼핑과 달리 남이 주말에 못 베낀다. 포지셔닝: **"AI 시대의 ESLint + Git Hook"** = 팔란티어식 표현으로는 **"경량 파일기반 온톨로지 + 액션 레이어"**(위키링크=엔티티·관계 / 파생봇·AGENTS.md=액션·룰 / doctor=자동 게이트키퍼). 2026-07-20 리서치로 확인(`[[project-btd-landscape-orca-ontology]]`) — 대기업 데이터인프라 전용 개념이 아니라 이미 BTD가 구현한 패턴임.
- **②직군 팩 = 소유하지 않는다.** 회사가 모든 직군 팩을 직접 만들면 유지보수 부채로 죽는다 → **"팩 생성 규격 + 레퍼런스 팩 1개(내 풀스택, 이미 dogfooding 중)"만 소유**, 나머지는 사용자/커뮤니티 authoring.
- **③협업층 = 가장 어렵다.** 그래서 **맨 나중.** 사내 스케일은 클라우드 실시간 동기화 없이 공유 git 레포로 충분.

## 2. 진입점 = 로컬 웹 대시보드

> CLI가 아니라 **로컬에서 뜨는 웹 대시보드**가 메인 진입점. 기존 `dashboard/`(엔진 `engine/serve.py` + `web/dashboard3d.html` 3D 오피스)의 "ai-company 관제판"이 그 프로토타입이다.

**두 가지 역할**
1. **초기 설정(셋업 마법사)**: 웹 화면에서 **직군 선택 → 기술스택·파생봇·템플릿·체크리스트 자동 세팅**. "동료가 Obsidian/G-Brain 규율 몰라도 클릭으로 세팅" = 온보딩 마찰 최소화.
2. **관제**: 세팅 이후 에이전트 협공 상황 모니터링 + 우체통으로 지시 (ai-company 대시보드 느낌).

**두 가지 배포 형태**
- **개인용 웹 대시보드**: 프리랜서·포폴용. 내 로컬에서만 돎.
- **사내·팀내 웹 대시보드**: 팀이 공유해서 봄. 볼트/우체통을 팀원끼리 공유.
- **호스팅/배포는 BTD가 책임지지 않는다 — 사용자가 알아서 배포**(로컬 실행이 기본, 팀은 각자 사내 인프라에 올림). BTD는 SaaS 호스팅 사업이 아님.

**아키텍처 갈림길**: 브라우저는 보안상 로컬 파일을 못 만진다. 볼트 스캐폴딩·`init`·팩 세팅을 실제로 수행하려면 **로컬 백엔드가 필수** → 대시보드는 "웹 UI + 로컬 서버(파일 워처 + 스캐폴딩 실행)" 구조.

**✅ 스택 결정 (2026-07-20, 그린필드 기준)**: **백엔드 Node/TypeScript + 프론트 React, 단일 TS 모노레포(프론트·백엔드 타입 공유).** 진입점 `npx btd`.
- 근거: 프론트가 React로 정해지면 백엔드도 TS여야 config 스키마·이벤트 타입·팩 정의를 **양쪽이 같은 타입으로 공유**(경계 이중정의·불일치 제거). npx 온보딩 관례 + 파일워처(chokidar)·실시간(ws) 생태계. 포폴로서도 모던 단일스택이 설명력↑.
- 기존 `dashboard/engine/`(순수 Python stdlib, 2,333줄)은 **버리지 않고 "검증된 레퍼런스 명세"로 TS 포팅 시 설계도로 참고**(프로세스 화이트리스트·이벤트 스키마·감사 로직). biz-ttori 실운영용으로는 TS 패리티 도달 전까지 그대로 가동.
- ⚠️ 재구현 최대 리스크 = 프로세스 관리·감사 로직(오포팅 시 엉뚱한 프로세스 kill). 완화: Python 엔진 병행 가동 + 나란히 검증 후 교체.

## 3. 개발 순서

```
1. ①뼈대 안정화 (지식그래프·우체통·doctor — 이미 biz-ttori에서 가동 중)
2. ②직군 팩 규격 + 레퍼런스 팩 1개(풀스택) + 로컬 웹 셋업 마법사
3. 로컬 웹 대시보드 관제 UI (개인용 먼저)
4. ③협업층 (사내·팀내 웹, 공유 git 레포) — 맨 나중
```

**포폴 서사(1순위 산출물)**: "에이전트 가드레일 시스템을 설계·구현하고, 실제 fanbird 라이브커머스 앱을 이 시스템으로 dogfooding하며 개발했다." → 완성도보다 **3층 구조 다이어그램 + dogfooding 케이스스터디 + 로컬 웹 데모(GIF/영상)**로 승부.

## 4. 안 할 것 (스코프 가드)

- ❌ 모든 직군 팩 직접 제작 (규격 + 레퍼런스 1개만)
- ❌ B2B SaaS 판매 / Stripe 구독 / 상용화 마케팅
- ❌ 클라우드 실시간 동기화(CRDT/OT) / SOC2·GDPR 인증 (사내는 git 레포로)
- ❌ 호스팅·배포 대행 (사용자가 알아서 배포)
- ❌ 특정 IDE·벤더 종속 (마크다운/CLI 규격으로 에이전트 무관하게)
- ❌ **v1 자가발전(셀프-디벨로핑 팩)** — 정적 팩으로 간다. 대신 `npx btd pack add <name>`로 사용자가 1초에 팩 추가/편집. 자가발전은 검증된 잠금장치 설계 후 future.
