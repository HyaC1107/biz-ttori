## 🎯 0. 목적 (2026-07-20 정정 — 최우선 프레임)

> **이 프로젝트는 판매(B2B SaaS)가 목적이 아니다.** 아래 두 가지가 진짜 목적이며, 우선순위는 **① 포트폴리오**.
>
> * **① 포트폴리오 (우선)**: "PM 본인이 에이전트 협업 가드레일 시스템을 설계·구현하고, 실제 fanbird 라이브커머스 앱을 dogfooding하며 개발했다"를 보여주는 것. → 완성도보다 **설명력**(3층 구조 다이어그램 · 케이스스터디 · 데모)이 핵심.
> * **② 프리랜서 개인용**: 1인 사업자가 여러 클라이언트 프로젝트(각각 `projects/<client>/`로 컨텍스트·계약 분리)를 오가며, 위임할 팀 대신 **에이전트에게 위임**. 혼자라 팀 동기화(③층)가 불필요해 구현 난이도가 가장 낮은 핏. 시스템 자체가 클라이언트 영업 도구도 됨.
> * **③ 사내 배포**: 자기가 다니는 회사 팀에 심어 실사용. → **온보딩 마찰 최소화**가 핵심. 사내 스케일 협업은 공유 git 레포면 충분(클라우드 CRDT/SOC2 불필요).
>
> 세 타깃 모두 **①뼈대 + ②직군 팩 층을 공유**하고, 사내 팀만 협업 층이 얹힌다 → 개발 순서는 **"①②층 먼저 탄탄히, 협업층은 나중"**.
>
> ⚠️ 아래 본문 중 "B2B SaaS", "Stripe 구독", "상용화 론칭", "경쟁사/가격", "플랫폼 리스크" 프레임은 **옛 기획(판매 목적)의 잔재**다. 판매를 안 하므로 수익화 모순·플랫폼 리스크는 사실상 무관하다(오히려 빅테크가 유사 기능을 내면 "먼저 실증했다"는 포폴 근거가 됨). 본문은 참고로 남기되, 판단 기준은 위 §0을 따른다.

## 🎯 1. 제품 개요 및 핵심 가치 (Value Proposition)

### 1.1 시장의 문제점 (Pain Point)
*   많은 개발팀과 1인 개발자들이 코딩 생산성을 극대화하기 위해 다중 AI 에이전트(Cursor, Claude Code, GitHub Copilot 등)를 현업에 투입하고 있으나, 아래와 같은 심각한 **"에이전트 충돌 및 통제 불능 리스크"**로 인해 실무 적용에 애를 먹고 있습니다.
    1.  **코드 오염:** 에이전트가 앞서 정의해 둔 전역 아키텍처와 코딩 규칙을 무시하고 자기 마음대로 코드를 덮어써서 기존 뼈대를 망가뜨림.
    2.  **환각 누적:** 단일 에이전트의 컨텍스트 소실로 인해 존재하지 않는 변수나 모듈을 호출(환각)하여 빌드가 깨지는 현상.
    3.  **오케스트레이션 부재:** 백엔드 전문 AI와 프론트엔드 전문 AI가 협공해야 할 때, 둘 사이에 상호 상태를 인지하고 소통하는 안전한 프로토콜이 없음.

### 1.2 솔루션 (Agent-Postbox의 해법)
*   **"다중 AI 코딩 에이전트 전용 가드레일 및 비동기 소통 솔루션"**
*   개발 프로젝트에 패키지 하나만 얹으면, AI 에이전트들이 **지정된 약속(AGENTS.md)을 준수**하고, **우체통 파일(Inbox/Outbox)을 매개로 상호 역할을 분담**하며, 커밋 전 **무결성 검사(Doctor)**를 통과하도록 강제하는 에이전트 오케스트레이션 가드레일을 제공합니다.

## 🛠️ 2. 핵심 기능 스펙 (Core Features)

### 2.1 CLI 개발자 도구 (npx 패키지)
개발자가 로컬 터미널에서 1초 만에 에이전트 협업 환경을 셋업할 수 있는 CLI 도구를 제공합니다.

1.  **`npx agent-postbox init`**
    *   현재 프로젝트 하위에 에이전트 협업 디렉토리 구조(`.agents/`, `memory/`, `tools/`)를 자동 스캐폴딩합니다.
    *   보편적인 개발 규칙 템플릿(`AGENTS.md`) 및 우체통 양식(`inbox.md`, `outbox.md`)을 생성합니다.
2.  **`agent-postbox doctor`**
    *   커밋/푸시 전, 지브레인 및 프로젝트 내 모든 위키 링크 무결성을 정적 분석하여 "깨진 링크나 정의되지 않은 소스 참조"가 발견되면 빌드/커밋을 중단시키는 환각 필터 엔진입니다.
3.  **`agent-postbox status`**
    *   현재 우체통(`inbox.md`, `outbox.md`)의 대기 중인 메시지를 파싱하여, 백엔드와 프론트엔드 에이전트가 어떤 상태에 머물러 있고 다음 R&R이 어떻게 배분되었는지 터미널에 요약 출력합니다.

---

### 2.2 설정 파일 규격 (`agent-postbox.config.json`)
에이전트 통제를 추상화하여 누구나 커스텀할 수 있게 만드는 중심 설정 도면입니다.

```json
{
  "projectName": "GwangjuON Portal",
  "postbox": {
    "directory": "./memory",
    "inbox": "inbox.md",
    "outbox": "outbox.md"
  },
  "agents": [
    {
      "name": "Gemini-Antigravity",
      "role": "Backend & Infrastructure Architect",
      "rules": "./.agents/rules/gemini_rules.md"
    },
    {
      "name": "Claude-Code",
      "role": "Frontend & UI UX Master",
      "rules": "./.agents/rules/claude_rules.md"
    }
  ],
  "guardrail": {
    "doctorScript": "./tools/gbrain-doctor.sh",
    "preventDirectPush": true,
    "requireCrossVerification": true
  }
}
```

### 2.3 로컬 웹 대시보드 (React/Next.js UI) — **초기설정 + 관제 겸용**
BTD의 메인 진입점은 CLI가 아니라 **로컬에서 뜨는 웹 대시보드**다. 두 가지 역할:
1. **초기 설정(Onboarding)**: 터미널 명령 대신 웹 화면에서 **직군 선택(풀스택 / AIoT / 기획 등) → 그에 맞는 기술스택·파생봇·템플릿·체크리스트가 자동 세팅**되는 셋업 마법사. (§0 온보딩 마찰 최소화의 핵심 — "동료가 규율 몰라도 클릭으로 세팅")
2. **관제(Monitoring)**: 세팅 이후엔 에이전트 협공 상황을 모니터링하고 우체통으로 지시하는 비주얼 관제판.

> 포폴 관점에서도 이 로컬 웹 대시보드가 **제일 강한 데모 표면**이다(CLI 로그보다 화면이 설명력이 높음).

## 📅 3. 3단계 개발 로드맵 (Roadmap)

### Phase 1: CLI 코어 엔진 개발 (1주일 소요)
*   **목표:** 터미널 명령어로 돌아가는 설치형 npm 패키지(`agent-postbox`) 빌드.
*   **세부 작업:** 
    *   프로젝트 스캐폴딩 스크립트 작성.
    *   정적 무결성 분석기(`doctor` 기능) Node.js 이식 및 패키징.
    *   npm 공식 레지스트리 배포 및 설치 테스트.

### Phase 2: 로컬 관제용 웹 UI 대시보드 개발 (2주일 소요)
*   **목표:** Next.js + Tailwind CSS 기반의 로컬 대시보드 웹 구동.
*   **세부 작업:**
    *   로컬 디렉토리의 파일 변경(inbox.md / outbox.md)을 감지하는 File Watcher(chokidar 등) 연동.
    *   에이전트 활동 타임라인을 슬랙/카카오톡 대화 폼 형태의 비주얼 피드로 시각화.
    *   대시보드 상에서 에이전트에게 텍스트로 우체통 편지를 직접 쏠 수 있는 입력 인터페이스 구축.

### Phase 3: 포트폴리오 패키징 & 사내 배포 (판매 아님 — §0 참조)
> 옛 계획의 "클라우드 SaaS 상용화 론칭(Stripe 구독)"을 **폐기**하고, 실제 목적(포폴+사내)에 맞게 대체.
*   **목표:** ① 포트폴리오로서 설명력 확보 ② 사내 팀 실배포.
*   **세부 작업:**
    *   **(포폴)** 3층 구조 다이어그램 + fanbird dogfooding 케이스스터디 문서 + 짧은 데모(GIF/영상) 제작.
    *   **(사내)** 마찰 없는 `init` 온보딩(동료가 Obsidian/G-Brain 규율 몰라도 쓰게) + 공유 git 레포 기반 팀 협업(클라우드 동기화·결제 불필요).
