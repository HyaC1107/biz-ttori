# 🛠️ 비즈또리(Biz-Ttori) AI 협업 인프라 & 스킬 이식 매뉴얼

본 매뉴얼은 **비즈또리**에서 검증을 마친 지식 관리 아키텍처(G-Brain)와 3대 자동화 스킬, 그리고 AI 통제 규칙들을 집에서 사용하는 개인 에이전트(**내또리**)에게 그대로 이식하여 생산성을 극대화하기 위해 작성된 종합 가이드라인입니다.

---

## 1. 🏗️ 비즈또리 협업 인프라 아키텍처: G-Brain

비즈또리는 AI 에이전트(클또리, 젬또리)와 인간 개발자가 **텍스트 지식 베이스(Obsidian)**를 공유하여 완벽하게 협업하는 **G-Brain(지브레인)** 방식을 적용하고 있습니다.

*   **단일 진실 공급원 (SSOT):** 모든 구현 설계서, 개발 회의록, 아키텍처 의사결정을 하나의 폴더에서 버전 관리하여 AI와 인간이 완전히 동일한 맥락(Context)을 공유합니다.
*   **비동기 협업 우체통 (inbox.md):** 젬또리가 팩트체크하거나 리서치한 분석 보고서를 우체통(`memory/inbox.md`)에 넣어두면, 교대 근무로 기동된 클또리가 이를 읽고 즉시 실제 소스 코딩으로 실현하는 비동기 이관 체계입니다.
*   **일일 일지 일원화 (Daily Logs):** 프로젝트별로 작업일지를 파편화하지 않고, 비즈또리 전역 일지 폴더(`daily/YYMMDD.md`)에 모으고 이미지 자산(`daily/attachments/`)을 정규화하여 관리합니다.

---

## 2. 🤖 내또리에게 장착 가능한 3대 핵심 커스텀 스킬

비즈또리 루트 디렉토리의 `.agents/skills/` 하위에 배치하여 검증을 완료한 **자동화 스크립트 3대장**입니다. 개인용 홈 에이전트 폴더에 이식해 활용하십시오.

### 2.1. 🩺 지식 검증 및 치료기: `gbrain-healer`
*   **역할:** 지식 베이스 내 마크다운 파일들의 깨진 `[[위키링크]]`를 자동 스캔한 뒤, 현존하는 파일명 유사도를 측정(Levenshtein Distance)하여 오타가 난 링크들을 안전하게 자동 보정(치료)합니다.
*   **핵심 로직 위치:** `.agents/skills/gbrain-healer/scripts/heal.js` 및 `tools/gbrain-doctor.sh`
*   **이식 팁:** 홈 디렉토리의 지식 저장소에서 링크가 404가 나거나 환각(Hallucination) 소스가 쌓이는 것을 방지하는 핵심 백신입니다.

### 2.2. 🗺️ 폴더-지도 동기화기: `gbrain-map-sync`
*   **역할:** `projects/` 하위의 실제 프로젝트 폴더들을 탐색하여, 지브레인의 전체 구조도인 `memory/g-brain-map.md` 내 프로젝트 노드 매핑 테이블을 자동으로 갱신하고 링크를 동화시킵니다.
*   **핵심 로직 위치:** `.agents/skills/gbrain-map-sync/scripts/sync.js`
*   **이식 팁:** 새로운 토이 프로젝트나 개인 공부 폴더를 루트에 생성했을 때, AI가 이를 자동으로 인지하여 전체 문서 맵에 링크를 걸어주게 할 때 유용합니다.

### 2.3. 🧹 임시 우체통 청소 비서: `inbox-cleaner`
*   **역할:** `memory/inbox.md`에 임시 기록된 리서치 보고서를 오늘 날짜의 일지(`daily/YYMMDD.md`) 하단 아카이브 영역으로 자동으로 이관(Cut & Paste)시키고, 다음 협업 세션을 위해 우체통 파일을 빈 상태로 깨끗하게 청소해 줍니다.
*   **핵심 로직 위치:** `.agents/skills/inbox-cleaner/scripts/clean.js`
*   **이식 팁:** 협업 히스토리가 날아가지 않고 일지에 누적 보관되도록 관리해 주는 자동 청소 루틴입니다.

## 3. 📝 AI 행동 통제 및 협업 규칙 세팅

AI 에이전트들이 제멋대로 행동하지 않고, 인간의 명확한 지휘 통제권 안에서 가장 효율적으로 움직이게 하는 **프롬프트 룰 셋업** 방식입니다.

### 3.1. 전역 AI 행동 강령 (`.agents/AGENTS.md`)
에이전트가 기동될 때 가장 먼저 읽고 따르는 최상위 바인딩 규칙 문서입니다. 내또리에게도 동일한 지침을 각인시키십시오.

```markdown
# 🤖 에이전트 프로젝트 규칙

1. **🔍 5대 검색 원칙 (S2):**
   * 공식 문서 우선 검색 (공식 레포, AWS/Google 등 공식 기술 문서 최우선 인용)
   * 날짜 및 패키지 버전 명시 필수
   * 커뮤니티 정보(블로그, Stack Overflow 등)는 반드시 다수 소스로 교차검증
   * 상충 정보 투명 표기 및 결론 근거 출처 URL 첨부 의무화
2. **📬 우체통(inbox.md) 발송 제한:**
   * 에이전트는 리서치 결과를 자발적으로 우체통에 밀어 넣지 않음. 오직 사용자가 "우편 보내줘", "인박스에 등록해줘" 등 명시적인 이관 지시를 내렸을 때만 우체통을 작성함.
3. **🧠 지브레인 단축 명령:**
   * 사용자가 "지브레인 체크해줘"라고 단독 입력하면, 즉시 `tools/gbrain-doctor.sh` 검증기를 돌리고 깨진 링크 발생 시 `heal.js`를 기동해 자동 교정 보고를 수행함.
```

### 3.2. 단축 빌드/검증 파일 (`CLAUDE.md`)
에이전트가 로컬에서 빠르게 빌드하고, 린트를 잡고, 무결성을 스스로 진단할 수 있도록 해주는 표준 커맨드 가이드맵입니다.

```markdown
# Biz-Ttori Developer Rules

## Build and Clean Commands
- G-Brain Doctor Check: `./tools/gbrain-doctor.sh`
- G-Brain Auto Healer: `./.agents/skills/gbrain-healer/scripts/heal.js`
- Clean Inbox: `./.agents/skills/inbox-cleaner/scripts/clean.js`
- G-Brain Map Sync: `./.agents/skills/gbrain-map-sync/scripts/sync.js`
```

---

## 💡 내또리 스킬 이식 로드맵
1.  개인 Obsidian 볼트(저장소) 루트에 `.agents/skills/` 폴더를 생성하고 위의 `.js` 자동화 스크립트 소스들을 복사합니다.
2.  에이전트의 전역 규칙인 `AGENTS.md`와 `CLAUDE.md`를 복사하여 에이전트의 초기 페르소나와 검증 커맨드를 셋업합니다.
3.  지식 정리용 인덱서인 `Daily.md`와 `g-brain-map.md`를 셋업하여 지식 베이스를 체계화합니다.
