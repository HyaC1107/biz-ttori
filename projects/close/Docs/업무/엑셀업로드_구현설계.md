## 1. 배경 — 기존 vs 새 요구 (구조 변경)

**기존** (`src/Page/Manage/LiveList/Component/Detail_itemInsert.tsx` L155~190)
- `엑셀 업로드` 버튼 → 숨은 file input → `.xlsx/.xls` 선택 → `product_excel_upload` API에 `{live_seq, file}` 통째 전송 → **서버가 파싱/등록**.
- 클라 매칭·미리보기·이미지 개념 **없음**.

**새 요구** (디자인)
- 버튼 → **모달** → 엑셀 + 이미지(들) 업로드 → **클라에서 xlsx 파싱** → 이미지 파일명 매칭 → 결과 테이블(성공/없음/오류) → `엑셀 업로드 완료` → 서버 등록.
- 파싱·매칭이 **서버 → 클라이언트로 이동**. (`xlsx ^0.18.5` 이미 설치됨)

## 2. 메인 모달 UI (디자인)

좌측(업로드) | 우측(매칭 결과 테이블)

- **엑셀 등록\*** (필수): 클릭/드롭 박스 → 업로드 시 파일명 칩(`2026-06-29 라이브 상품목록.xlsx` + X).
- **이미지 등록**: 클릭/드롭 박스. `* 업로드 형식: jpg, png, zip`.
- **매칭 결과 카운터**: `총 이미지 N / 매칭 완료 N / 사용 안함 N`.
- **필터 탭**: `전체 / 성공(n) / 없음(n) / 오류(n)`.
- **테이블 컬럼**: 상품명 · 가격 · 재고 · 옵션 · 이미지(썸네일) · 상태 · 오류.
  - 상태: `성공`(초록) / `없음`(회색) / `오류`(빨강).
  - 오류 행: "총 N개의 오류가 있습니다" 아코디언 → 상세 리스트.
- **엑셀 업로드 완료** 버튼: 엑셀 없으면 비활성(회색), 있으면 보라 그라데이션(`linear-gradient(135deg,#7955f0,#3209b9)`).

## 3. 내부 상태/에러 팝업 8종 (트리거 매핑)

| 팝업 | 트리거 | 버튼 |
|:---|:---|:---|
| 지원하지 않은 양식 | 이미지에 jpg/png 외 확장자 | 확인 |

| 이미지 손상 | 이미지 디코드 실패 | 확인 |

| 사용되지 않은 이미지 | 엑셀에 없는 이미지 (썸네일 목록) | 확인 |
| 엑셀 재업로드 시 초기화 | 엑셀 이미 있는데 새 엑셀 | 취소 / 확인 |
| 엑셀 삭제 시 초기화 | 엑셀 칩 X 클릭 | 취소 / 확인 |
| 오류 무시 후 등록 | 완료 시 오류 N건 존재 | 취소 / 확인 |

## 5. 🚧 PM 확정 대기 (설계 확정 전제)

### Q1. 최종 전송 방식 (백엔드 계약)
- (A) 기존 `product_excel_upload` 재활용 — 엑셀+이미지 함께, 서버가 등록 (백엔드 협의 필요)
- (B) `product_create` 반복 호출 — 클라 파싱 데이터로 상품마다 등록 (백엔드 무변경)
- (C) 새 전용 API 신설 (계약 정의 필요)
- (D) 미정 — 프론트 UI/파싱/매칭 먼저, 전송은 stub

### Q2. 엑셀 양식 (컬럼 헤더 + 이미지 파일명 참조 규칙)
- 상품명/가격/재고/옵션/이미지 컬럼의 **정확한 헤더명**
- 이미지 파일명이 **어느 컬럼**에, 여러 장이면 **구분 방식**(콤마? 여러 컬럼?)
- 옵션(예: "사과맛 1+1") 구조 — 현재 `product_create`엔 옵션 필드 없음. 옵션 등록 경로(`option_tag_create`?) 확인 필요

### Q3. 상품당 이미지 매칭 단위
- 디자인상 "마이쮸"가 옵션별 여러 행 → 이미지가 **옵션 행 단위**인지 **상품 단위**인지
