fanbird 송출 RN 앱(Native Bridge Phase 1) 작업 중 **다른 팀 확인이 필요한 항목** 정리.
🔴=E2E 진행 블로커 / 🟡=확인 필요 / 🟢=Phase 2·후속

## 1. 백엔드 팀

- 🔴 **`aws-ivs/getStreamInfo` 응답 스펙 확정**: 앱이 `streamKey` + `I_Epoint`(ingest endpoint)를 받아 `rtmps://<I_Epoint>:443/app` 형태로 송출한다. **(a) 응답 필드명/형태**, **(b) I_Epoint가 호스트만인지 vs 스킴·경로 포함인지** 확인 필요(URL 조립 방식이 달라짐).
- 🟡 **`live/get-live-info` 응답의 `live_title`**: 방송화면 헤더 제목이 "4"로 표시됨 — 테스트 데이터 값인지, 응답 필드/형태 문제인지 확인.
- 🟡 **소켓(Socket.io) 이벤트 재사용 확인**: 웹과 동일 서버/경로(`/socket.io`)·이벤트(`Duration Time`, `Viewer Count`, `Stock`, `Stock Over`)를 RN에서 그대로 쓰는 게 맞는지, 페이로드 형태 동일한지.
- 🟡 **인증 토큰/리프레시**: 웹 `axios_Interceptor` 로직 그대로 포팅함. seller-login/refresh가 RN(모바일 클라)에서도 동일 동작하는지(만료/재발급).
- 🟡 **채팅 토큰** `aws-ivs-chat/createChatToken` RN에서 정상 동작 확인.

## 2. 인프라 / AWS 담당

- 🔴 **개발용 IVS 채널 + 테스트 스트림키 발급**: 실제 송출(RTMPS) End-to-End 검증의 핵심 블로커. 이게 없으면 "카메라 프리뷰"까지만 확인 가능하고 실제 방송 송출은 검증 불가.

## 3. PM / 기획

- 🔴 **Apple Developer Program 계정**: 실기기 설치(7일 초과)·TestFlight·스토어 배포에 필요. 누가 제공하는지.
- 🔴 **실기기 확보**: iOS 실기기 + Android 실기기(각 1대 이상). 시뮬레이터/에뮬레이터는 카메라 프리뷰가 GPU/EGL 한계로 검은 화면 → 실기기에서만 최종 확인 가능.
- 🟡 **실송출 연동 착수 시점**: 이전에 "프론트 정리 먼저"로 정함 — 위 스트림키/계정/기기 확보 타이밍 조율.
- 🟡 **폴드/태블릿 지원 범위**: 폴드 커버 화면(폭 좁음)에서 레이아웃 이슈 발견·수정함. 폴더블/태블릿을 공식 지원 대상으로 볼지, 일반 폰만 볼지 확정 필요(디자인 QA 범위와 직결).
- 🟢 **백그라운드 송출 정책 재확인**: iOS는 OS 제약으로 백그라운드 카메라 캡처 불가(화면 자동잠금 방지까지가 현실적), Android는 Foreground Service로 가능. 정책상 "유지"였으나 iOS 제약을 재공유·확정 필요.

## 4. 디자인 팀

- 🟡 **Phase 1 잔여 화면 목업**: 판매상품 팝업, 공지사항, 소리설정 — 실제 목업이 있는지(현재 웹 로직 기반 추정 구현 상태).
- 🟢 **Phase 2 신규 기능 목업**: 뱃지 설정 / 판매창 색감 변경 — 기존 웹에 없는 신규 기능이라 목업 자체가 없음. 기획+디자인 확정 필요.
- 🟡 **폴드/좁은 폭 화면 디자인 가이드**: 상단 상태바(LIVE·타이머·시청자수·시작/종료 버튼) 등 좁은 폭에서의 우선순위/말줄임 기준.
