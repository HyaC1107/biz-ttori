# team-rules.md — 업무 및 협업 교훈 규칙

이 문서는 **Biz-Ttori** 환경에서 AI 팀원들과 작업을 수행하면서 겪은 문제들과, 이를 해결하기 위해 축적된 사내 협업 규칙 및 모범 사례를 기록합니다.

---

## 🤝 협업 기본 원칙

1. **설계 없는 코딩 금지 (Plan-First)**:
   - 모든 기능 구현은 최소한의 구현 범위와 구조 설계를 공유하고 PM(사용자)의 컨펌을 받은 뒤 시작한다.
2. **코드리뷰 게이트 준수 (Review Gate)**:
   - 외부 API 연동이나 스키마 수정 등 크리티컬한 변경점은 ① 린터/타입체커/테스트(결정론적 도구)를 먼저 통과시키고 ② `reviewer` 분신(작성 분신과 분리, adversarial)으로 검토한 뒤 ③ 필요 시 `coderabbit`(cross-model)으로 보강한다.
   - ※ 챗또리(codex) 보류 중. 재도입 시 ③을 codex 외부 검증으로 승격.
3. **독립성 유지**:
   - 하위 에이전트(coder, reviewer 등)는 최종 결과를 파일로 저장하지 않고 지휘자 클또리에게 리턴하며, 승인 및 저장은 클또리가 책임지고 수행한다.
4. **젬또리 검색 및 검증 원칙 (S2)**:
   - 젬또리(Antigravity)는 리서치 및 문서 검증 시 5대 검색 원칙(① 공식 문서 우선, ② 날짜/버전 명시, ③ 교차검증, ④ 상충 정보 명시, ⑤ 출처 첨부)을 반드시 적용한다.

## ✍️ 커밋 및 문서화 컨벤션

### 1. Git 커밋 메시지 규칙
협업 과정에서 AI가 작성하는 커밋 메시지는 사내 가이드에 따라 명확하게 통일합니다:
* `feat`: 새로운 기능 추가
* `fix`: 버그 수정
* `docs`: 문서 수정 (Markdown, README 등)
* `style`: 코드 포맷 변경, 세미콜론 누락 등 (비즈니스 로직 변경 없음)
* `refactor`: 코드 리팩터링
* `test`: 테스트 코드 추가 및 수정
* `chore`: 빌드 설정, 패키지 매니저 설정 변경 등

*예시*: `feat(api): 사용자 로그인 API 및 JWT 발급 추가`

### 2. Obsidian 문서 태그 체계
* **진행도**: `#status/진행중` `#status/완료` `#status/보류`
* **노트 유형**: `#type/spec` (기획서) `#type/api` (API 명세) `#type/reports` (업무 보고) `#type/daily` (일일 업무 일지)
* **카테고리**: `#tech/react` `#tech/rn` `#tech/node`

2. **[2026-06-30] 문서 드리프트 = AI 혼란의 실재 원인**: 체제를 2인(codex 보류)으로 바꿨는데 triggers/team-rules/README엔 "챗또리 필수 리뷰"가 남아 세션 시작 시 클또리가 잘못 학습할 위험이 있었음. → 정책을 바꾸면 **참조하는 전 문서를 같은 턴에 동기화**하고, 끝나면 `grep`으로 잔재(옛 용어)를 훑어 검증한다. 단일 진실원(SSOT)은 CLAUDE.md.
3. **[2026-06-30] context.md는 스냅샷 전용**: 완료 이력이 쌓여 비대해지면 세션 시작 읽기가 무거워짐 → 이력은 `CHANGELOG.md`로 분리, context.md는 "지금 상태/다음 할 일/블로커"만 1화면 이내로 유지.
4. **[2026-06-30] 외부 제안은 "코어만 취하고 함정은 버린다"**: 지브레인(G-Brain) 원안을 그대로 따랐으면 ① 함수단위 링크 부패(자기가 막겠다던 환각을 자기가 생성) ② 글로벌 레이어분할(프로젝트 호스트엔 틀린 축) ③ 매작업 thought 강제(지갑방어 위반)를 떠안을 뻔함. → 멋진 제안일수록 **우리 단계·구조에 맞는지 검증 후 정제 채택**. 링크 체계는 **부패 점검기(`gbrain-doctor.sh`)를 동반할 때만** 자산이다(없으면 부채).
5. **[2026-06-30] 젬또리 설계검토(T1) 선별 — 외부 리뷰도 100% 수용 금지**: 7건 중 3건만 채택. **채택**: ① api-specs SSOT 이중화(전역 vs 프로젝트별) = 실제 자기모순 버그 → 프로젝트별 SSOT로 일원화 ② T3 분신 캡은 소프트(프롬프트)이지 하드캡 아님 → 문구 정직화+완화책 ③ 기동≠cwd 구분(외부 빌드는 레포 cwd에서). **기각**(재발방지용 기록): ⓐ "벡터 RAG 시급" → 20노트·0프로젝트엔 과잉, grep으로 충분(2턴 전 PM과 보류 결정 그대로) ⓑ "외부 수정 시 CLAUDE.md 규칙 누실" → 세션 내 CLAUDE.md는 유지됨, 추가 로드는 가산적이라 메커니즘 오해(젬또리도 '추정' 표기) ⓒ "symlink로 wikilink 되니 제약 불필요" → 기술적 사실이나 node_modules/.git 인덱싱 오염으로 의도적 비채택. **교훈: 외부 리뷰는 적대적으로 재검증 후 선별 적용한다.**
