B안(소켓 딜레이 트릭) 대신, **AWS IVS가 공식 권장하고 지원하는 Timed Metadata (A안) 표준 API를 처음부터 즉시 적용하기로 결정**했어.

---

## 🎯 PM 최종 결정 사항
* **개발 방향:** **AWS IVS Timed Metadata (A안) 연동으로 확정.**
* **이유:** 소켓 딜레이 방식(B안)은 송출 인코딩 지연 누락 및 네트워크 버퍼 드리프트로 인해 영상과 팝업 싱크가 수 초씩 어긋나는 치명적인 함정이 있어, 라이브 커머스의 핵심 사용자 경험을 위해 0.1초 미만 오차 없는 공식 API(A안)를 바로 구축하기로 함.
* **백엔드 협업:** 백엔드 개발 파트에서 어드민 [판매 노출] 신호를 감지해 AWS SDK의 `PutMetadata` API를 트리거하도록 공조를 요청할 예정임.

---

## 🛠️ 향후 구현 시 조치 사항
* **시청자 웹 플레이어 (`Live_Component.tsx`):**
  * `amazon-ivs-player`에 `PlayerEventType.TEXT_METADATA_CUE` 이벤트 리스너를 구현해 줘.
  * 큐(Cue)에 들어오는 상품 메타데이터 JSON(예: 상품 ID 등)을 파싱하여, 즉시 상품 팝업 UI를 표출하도록 바인딩해 줘.
* **송출자 모바일 앱:**
  * 백엔드 API를 경유하여 프레임에 메타데이터가 실리기 때문에, 모바일 송출앱단에서 자체적으로 메타데이터를 주입하는 `queueMetadata` 등은 구현하지 않아도 돼.
