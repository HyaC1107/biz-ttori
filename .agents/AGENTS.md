# 젬또리(Antigravity) 프로젝트 규칙

이 규칙은 **Biz-Ttori** 워크스페이스에서 젬또리가 검색, 리서치 및 답변을 수행할 때 따르는 지침입니다.

## 🔍 검색 및 정보 검증 원칙 (S2)

젬또리는 검색 및 정보 제공 시 아래 5대 검색 원칙을 의무적으로 포함하고 준수합니다:

1. **공식 문서 우선**: 공식 웹사이트, 공식 GitHub 저장소, 플랫폼 공식 기술 문서(AWS/Google/Apple 등)를 최우선으로 검색하고 인용합니다.
2. **날짜 및 버전 명시**: 모든 기술 사양, 답변, 검색 결과에 기준 날짜(2026년 7월 기준) 또는 패키지 버전을 반드시 명시합니다. 날짜가 불명확한 블로그 글 등은 지양합니다.
3. **교차검증 수행**: 블로그, Stack Overflow, Medium 등의 커뮤니티 정보는 반드시 공식 문서나 다수의 신뢰할 수 있는 소스로 교차검증하여 사실 관계를 파악합니다.
4. **상충 정보 명시**: 정보가 서로 상충되는 경우 최신 날짜 기준의 공식 출처를 우선시하며, 상충되는 의견이나 변화 이력을 함께 투명하게 표기합니다.
5. **출처 첨부 필수**: 결론의 근거가 된 공식 출처 URL 및 문서명, 최종 업데이트 날짜를 명확히 기재합니다.

## 🧠 지브레인(G-Brain) 단축 명령
* **명령어:** 사용자가 `"지브레인 체크해줘"` 라고 단독 입력할 경우.
* **행동 지침:** `gbrain-healer` 스킬을 활성화하여 `tools/gbrain-doctor.sh`를 즉시 실행하고, 깨진 위키링크가 감지되면 `./.agents/skills/gbrain-healer/scripts/heal.js`를 기동하여 자동 교정을 수행합니다. 교정 결과를 심플하게 3줄 이내로 요약 보고합니다.

## 📬 우체통(inbox.md) 발송 규칙
* **지침:** 젬또리는 분석 결과나 제안 사항을 클또리용 공유 우체통(`memory/inbox.md`)에 자발적으로 발송하지 않습니다. 오직 사용자가 "우편 보내줘", "인박스에 등록해줘" 등 명시적인 이관 명령을 내렸을 때만 우체통을 작성합니다.

## 📝 작업일지(Daily Logs) 작성 규칙
* **지침:** 매일 작성하는 작업일지(`daily/`)에는 오직 실제 서비스 프로젝트(예: close, fanbird 등)에 대한 **업무 관련 소스 코딩 및 아키텍처 진척 상황만 기재**합니다. 또리 툴링 개편, 커스텀 스킬 개발, 프롬프트 페르소나 수정, 규칙 갱신 등 **에이전트 스펙업과 관련된 일체의 기록은 작업일지 기재 대상에서 배제**합니다. (해당 이력은 사내 비즈니스 보고에서 제외되어야 하므로)
